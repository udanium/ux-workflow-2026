Intro

Since January 2025, when I was laid off from a climate-tech startup, I’ve spent more than 20 months watching and engaging with the shifts reshaping UX and the wider tech industry. I haven’t only observed the AI revolution. I’ve worked inside it, creating designs, plans and strategies for small AI startups pushing toward agentic workflows.

My own workflow has changed too. AI is now my sparring partner: it checks my blind spots, generates first drafts of interactive prototypes, and lets me engage users and clients through live prototypes. But I still make maps, models and diagrams when I need to think through higher-order concepts or see something whole.

All the while, “AI and UX” reports kept appearing in my LinkedIn feed. I skimmed and parsed them one at a time, but I wanted to see what happens when they converge: which dots connect, and which patterns emerge in one giant, meta-level report. This is the result, and I wanted to share it with you. It’s built on an AI-generated analysis of those AI and UX reports, so there are many levels of meta going on here. I hope you find value in it. One pattern stood out to me most: as making gets cheap, the contested work is framing the problem, which is exactly what those maps and models are for.

In 2026, AI in UX stopped being a set of add-ons and became part of how design work is organized.

Agents now work on the canvas and in code. The Model Context Protocol carries context between design files, design systems, research and code. Skills turn a team’s conventions into instructions agents follow.

When producing UI costs little, the value moves to framing problems, building context and judging what comes back.

Validation can start earlier and at higher fidelity. The risk is committing to a solution before the problem is framed, which makes deliberate divergence and problem framing more important, not less.

A ledger of judgment

David Hoang argues that when finished-looking output is cheap, the artifact no longer proves the work. Credibility has to come from the decision trail: the context gathered, the options rejected and the tradeoffs made. Agents need the same trail, and he names four requirements for trusting their work: visible execution, scoped access, reviewable history and reversible actions. Proof of Concept

The canvas opens to agents

Moves production toward agents

In three months, outside agents got onto the Figma canvas, Anthropic launched a conversational design tool, and Figma shipped its own design agent.

  1. March 2026 Outside agents on the canvas

    Figma’s use_figma tool lets Claude Code, Codex and other MCP clients create and edit Figma assets tied to a team’s design system. A companion tool turns live HTML into editable layers, closing the loop from code to canvas and back. Figma

  2. April 17, 2026 Claude Design launches

    A conversational canvas for prototypes, wireframes and decks that applies a team’s design system automatically. More than a million people used it in its first week. It now checks output against imported design systems and hands off to Claude Code without falling back to a screenshot. Anthropic

  3. May 2026 Figma’s own design agent

    Works with a team’s components and tokens, explores several directions in parallel, handles bulk edits such as dark mode and component swaps, writes documentation, and turns comment threads into prioritized revisions. It’s now generally available. Figma

Other prompt-to-product agents include v0, Bolt, Lovable and Framer AI.

What it means for the process

Repetitive production work, such as states, variants, content fills and documentation, moves to agents. Exploration gets wider and cheaper, so the designer’s job shifts toward choosing among options and refining the chosen one.

MCP becomes the connective layer

Moves work into shared infrastructure

The Model Context Protocol lets agents read from and write to design tools in a structured way, so context flows in both directions instead of being handed off once.

The Figma MCP server passes frames, components, variables and layout data to coding agents such as Claude Code, Cursor and GitHub Copilot. Figma is explicit that it supplies design context, not finished production code. Code Connect maps Figma components to the components in a real codebase, so generated code uses them instead of guessing. The server now works with more than 20 partner clients. Figma

The reach goes well beyond Figma. Uber runs an internal MCP server for its Base design system, and Atlassian offers a server and a CLI for its own. Lyssna and Great Question let teams query research studies from Claude or ChatGPT, and coding agents can now read and write FigJam boards.

Figma’s 2026 survey describes the result as a continuous loop: anyone can start in code or on the canvas and move between them before shipping, and over half of respondents say they’ve stopped using linear handoffs entirely. Teams still differ on how they move: 37% work sequentially, 32% in iterative rounds and 23% in parallel. Figma

What it means for the process

The handoff becomes a continuous loop rather than a single moment. Keeping design and code in sync becomes ongoing infrastructure work.

Skills encode team judgment

Moves judgment into shared infrastructure

Skills are markdown instruction files that agents load when they’re relevant. They turn a team’s steps, sequencing and conventions into rules agents follow while they work.

Figma describes conventions as “no longer static documentation.” Skills also support self-correcting loops: the agent screenshots its own output and fixes whatever doesn’t match the design system. Figma

What it means for the process

Writing down tacit expertise becomes a core design practice. Whoever writes and maintains a skill shapes the output of every agent that uses it, which raises new questions about who owns skills and how they’re reviewed.

Design systems become agent infrastructure

Moves work into shared infrastructure

The design system’s audience now includes machines. What agents can reach decides whether they produce on-brand work or generic work.

An agent-ready system has machine-readable tokens, documented component APIs, parity between Figma and code, and usage rules written as checks rather than review comments. Teams feed it to agents in one of three ways. Headway

Live MCP server

Task-based routing

zeroheight’s 2026 outlook names three priorities: MCP servers with skills and guidelines, designing in code, and documenting the when and why behind components. State of AI in Design Systems

One file for people and agents

The static-file approach now has an open format. Google Labs open-sourced DESIGN.md in April 2026: one plain-text file at the root of the repository, with machine-readable tokens at the top and the rationale behind them, written for people, below. A command-line tool lints the file and exports its tokens. Google Labs

Patrick Neeman argues it’s the standard file design needs for the agent era, the one place both a team and its agents read as truth. Not everyone is convinced: one critic points out that design tokens already have formats such as W3C DTCG and Tailwind, so DESIGN.md adds a layer rather than consolidating them. What it means for the process

Design system teams take on a platform-engineering role. Recording why a component exists, not just what it is, decides whether agents generate on-brand work or generic work.

Research workflows split three ways

Moves fieldwork toward agents, while judgment stays with researchers

AI research tools now fall into three groups: tools that run research, tools that capture it, and tools that synthesize it. Perspective AI

Run

AI-moderated interviews, from tools such as Marvin and Dovetail’s agents.

Capture

Testing platforms that record sessions and responses.

Synthesize

Auto-coding and synthesis that cites its sources.

Synthetic participants have appeared too, from tools such as Synthetic Users and Uxia, alongside Dovetail’s digital twins. In a side-by-side test, synthetic users caught surface-level problems but missed how real users actually behave. They worked best as a fast, automated heuristic review. The Good

35.7%
of designers never use AI for research synthesis, one of the least-adopted uses. Designlab

What it means for the process

Research can run faster and continuously, but deciding what counts as evidence becomes a methodological and ethical question. Researchers spend more of their time framing studies, verifying findings and interpreting them.

Designers become orchestrators of agents

Moves designers toward direction

Advanced practitioners now run several agents in parallel, and splitting the work that way turns design into a management job.

Claude Code offers experimental agent teams with shared task lists and plan approval, Codex runs parallel cloud tasks, and OpenPencil runs concurrent agents across regions of one canvas. Agentic Design School describes the job that results. Agentic Design School

  1. Break the work into parts.
  2. Write the contract each worker follows.
  3. Set the quality gates.
  4. Review the merged result.

Enterprise designers are also building microtools and agentic workflows that let non-designers produce on-brand work from prebuilt components. Designer Fund

What it means for the process

The designer’s role moves from making things to directing and curating them. Briefing, quality gates and review become explicit design skills.

The diamond debate

Cheap building has reopened the argument about the Double Diamond. Five camps have formed. Scroll through them and watch what each does to the shape.

The Double Diamond

Discover, Define, Develop, Deliver: diverge and converge, twice.

Four phases, two diamonds

The Design Council’s Double Diamond frames design as two rounds of diverging and converging: Discover and Define to find the right problem, Develop and Deliver to find the right solution.

Between mid-2025 and October 2026, proposed revisions fell into five groups.

The doubts predate generative AI. In 2023, Richard Eisermann, who led the team that created the model, said it was “probably not” still fit for purpose: it reads as a straight line and has no step for measuring outcomes. Muzli

Augment: AI in every phase

Keep the four phases. Give each one an agent, and make the points where people decide explicit.

  • Augmented Double Diamond Hor et al., Research-Technology Management, August 2026

    An agent per phase for empathy, problem framing, ideation and iteration. People steer through validation, direction and learning loops. It’s already taught in business schools.

    Peer-reviewed, not empirically tested
  • A2D2

    An AI engine at the front of each diamond, with explicit decision points for humans.

    Practitioner model
  • Control levels by phase Korean study

    Discover and Develop are collaborative, Define is human-led, and Deliver is AI-led with human oversight.

    Academic study

Extend: new phases, new outputs

Rename the phases for agentic work, and add steps the original never had.

  • Agentic Double Diamond UXmatters, March 2026

    Discover becomes synthetic research, Define becomes intent mapping, and Develop becomes behavioral prototyping. A fifth phase, Adapt, follows delivery.

    Practitioner model
  • Agentic Double Diamond ASDLC, July 2026

    Each diamond is a “context furnace” that turns messy input into machine-readable specs. Adversarial gates at each convergence stop teams from building before the problem is defined. The spec becomes the product’s real source code.

    Practitioner model

Defend and test: compressed, not dead

Reframe the model as risk management, then check it against how designers actually work.

  • NN/g Gibbons and Wang, March 2026

    Designers who seem to skip steps have internalized the process and compress it. Solution-first work suits only mature problem spaces, and its success stories may reflect survivorship bias. The answer is process literacy: choosing how much process a problem warrants.

    Expert analysis
  • Design observability Google, CSCW ’26

    Across 4,036 version snapshots from 102 Figma files, work sat in ideation 93% of the time, and 80% of prototyping and 75% of testing transitions led back to it. Practice loops; it doesn’t run in a line.

    Empirical study
  • Survey of 443 designers

    AI use peaks in Discover at 72% and falls to 41% in Deliver, the reverse of where AI design tools are concentrated.

    Survey
  • Design Science review Cambridge

    The convergence points are the diamond’s strength for AI. They force outputs through selection and justification instead of letting them pile up.

    Academic review

The Design Council hasn’t published an AI-specific revision. Its latest evolution of the model is the 2021 Systemic Design Framework, which predates generative AI.

One practitioner reports that the Council’s Chief Design Officer described that framework, at a June 2026 panel, as the Council’s answer for complexity. Pundarik Ranchhod

What the revisions share

  • Building used to be the risky step. Now it’s cheap.
  • The second diamond shrinks while generation widens.
  • Convergence points become the places where people keep control.
  • A measure-and-learn step gets added, closing the gap Eisermann named.
  • Briefs and specs are written for agents to execute, not only for people to read.

Problem framing is the disputed ground.

Wen and Neeman treat it as something to compress. NN/g, the Augmented Double Diamond and ASDLC treat it as what must be protected.

The real disagreement is about who gets to frame problems, and on what evidence, once building is cheap.

            What this means for design leaders

            Seven takeaways drawn from the evidence above. Two are about the infrastructure agents depend on. Five are about the human work around it.

            The infrastructure agents depend on

            • Treat context as a strategic asset

              Agent output is only as good as the design system, skills and research the agents can reach. Funding that infrastructure is now a leadership responsibility.

            • Govern the skills layer

              Skills turn judgment into executable rules. They need owners, review and versioning, the same discipline a design system gets.

            The human work around it

            • Rebuild collaboration on purpose

              With collaboration thinning and learning moving to peers, create shared critique spaces, showcases for workflows and protected time to experiment. A tinkering culture doubles the likelihood that designers feel more creative and capable.

            • Re-establish design’s standing upstream

              As production costs fall, design’s credibility depends on problem framing, research rigor, and holding the quality bar across roles that now overlap.

            • Protect the pipeline for junior designers

              Agents absorb the production tasks juniors used to learn on. Teams need new apprenticeship paths, such as reviewing agent output, writing skills and assisting with research.

            • Make evidence standards explicit

              As synthetic participants and automated synthesis spread, teams should state what counts as user evidence for each decision.

            • Keep a ledger of judgment

              When finished-looking work is cheap, credibility comes from the trail behind it: the context, the options rejected and the tradeoffs made. The same trail is what lets people trust what agents did.
